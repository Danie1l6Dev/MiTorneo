# Reglas de trabajo con git

- No crear ramas nuevas. Trabajar siempre directo sobre `develop`.
- No hacer commits, aunque en algún momento anterior de la conversación se haya aprobado un commit similar. Dejar los cambios sin commitear.
- No usar el flujo de worktree (EnterWorktree) para tareas en este repo — se trabaja directo en el checkout de `develop`.
- Si al terminar una tarea quedan cambios sin commitear, avisar qué archivos cambiaron y por qué, y dejar que el usuario decida si los commitea.
- Si el usuario pide explícitamente hacer un commit, push o crear una rama en un mensaje puntual, se puede hacer para esa acción específica — eso no cambia la regla por defecto para el resto de la sesión.

# Idioma

- Usar español neutro, sin voseo ni argentinismos ("vos", "podés", "tenés", "acá", "che", "dale", conjugaciones como "corregí"/"completá", o palabras como "inscripto" en vez de "inscrito"). Aplica tanto al chat con el usuario como a cualquier texto en español que se escriba en el código (labels y descripciones de vistas, mensajes flash, textos de validación, comentarios en español).
